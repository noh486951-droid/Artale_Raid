# Artale Raid Commander Pro

Artale Raid Commander Pro 是一款專為線上遊戲副本與公會活動設計的智慧排程與戰績管理系統。透過結合前端視覺化介面及後端 Google Apps Script 資料庫，提供自動化的團隊協作方案。

## 🌟 版本更新 (V1.6.0)

- **統計口徑修正**：之前把一次「發布 MISSION」當成一場，但實際上一次發布是全員各打 7 場，6 人出團就是 42 場次。分母錯了 40 倍以上，掉寶率被大幅高估。現在所有統計改以「場次」為單位。
- **開寶率改為件數 ÷ 總場次**，顯示到小數點後兩位。評級重新分級：5% 以上佛心、2~5% 大方、1~2% 小氣、低於 1% 「越打越窮」。
- **連續槓龜門檻重設**：舊門檻（8／15 場）半週就達標，全團永遠 💀，梅完全失去意義。現改為 50／100／200 場次，符合 1~2% 掉寶率下平均 50~100 場才掉一次的實際情況。

## 🌟 版本更新 (V1.5.9)

- **新增連續槓龜計數器**：從最近一場往回數，連續幾場沒拿到東西。戰績排行榜新增「連續槓龜」欄位（達 8 場出現 🐢、15 場出現 💀）；副本區塊也會顯示「這王已經連續 N 場沒給東西了」。
- **開寶率評級調整**：Artale 本來就很難掉，10% 以上改列為「佛心來著」，5~10% 為「還算大方」，低於 5% 維持「越打越窮」。

## 🌟 版本更新 (V1.5.8)

- **新增副本開寶率**：戰績排行榜下方新增「副本開寶率」，計算方式為「有掉東西的場次 ÷ 總場次」，並依比率高低配上不同評語（低於 5% 會出現「越打越窮」）。
- **掉落紀錄新增場次歸屬**：`Drops` 往後新增「週次」與「時段」兩欄，每筆掉落才能對應到具體哪一場。沒有這兩欄就算不出開寶率，也分不出掉落發生在哪一週。舊資料的前四欄位置不變，照樣讀得到。
- **Discord 自動播報**（需搭配後端）：每週一發「上週戰利品快報」，每月 1 號發「戰績月報」，含歐皇、苦主、最勤勞稱號與各王開寶率。

## 🌟 版本更新 (V1.5.7)

- **存檔驗證跳過後端快取**：後端（Google Apps Script）現在會把資料快取 30 秒。一般讀取走快取，但送出排程或掉落後的「確認真的寫進去了嗎」會帶 `fresh=1` 跳過快取，避免讀到舊資料而把成功的儲存誤判成失敗。

## 🌟 版本更新 (V1.5.6)

- **修正登入不進去**：上一版把第一次請求的逾時設為 8 秒，但實測 Google Apps Script 的正常回應時間介於 6 到 17 秒，等於把那些只是比較慢但其實會回來的請求直接砸掉。
- **改用「補發」而不是「逾時重來」**：第一發超過 9 秒還沒回來就再補一發，但**不取消前一發**，誰先回來就用誰，最多三發、整體上限 32 秒。慢的請求不會被白白丟掉，卡死的請求也不會拖著整個畫面。

## 🌟 版本更新 (V1.5.5)

- **修正開啟頁面永遠轉圈圈**：Google Apps Script 的請求有時會卡住不回應（實測會停在 302 重導向那一跳超過 20 秒），而原本的 fetch 沒有任何逾時，所以畫面會一直停在「連線至資料庫中...」。現在每次請求都有逾時上限，第一次 8 秒走快路徑，第二次放寬到 18 秒因應伺服器忙碌的情況。
- **載入過程會顯示進度**：重試時會明示「Google 伺服器沒回應，重試中（第 N 次）」，不再是沒有任何回饋的轉圈。
- **連線失敗可以重試**：失敗畫面改成顯示具體原因加上「重新連線」按鈕，不用手動重整整個頁面。
- **降低對 API 的壓力**：回到前景的自動重抓間隔由 20 秒拉長為 60 秒（整包資料超過 50KB，打太勤會把端點拖垮）。

## 🌟 版本更新 (V1.5.4)

- **掉落分配可以一人多件**：以前每人只有一個下拉，同一場拿到兩樣東西就得送兩次。現在每人都有「＋ 再加一件」按鈕，可以一次登記多件（含同款多件），送出後的驗證也改成逐筆比對數量，部分寫入失敗會被拓出來。
- **分配名單改用實際參戰名單**：以前名單是抓「誰報名了這個時段」，與實際到場的人可能對不上，外援更是根本不會出現。現在改用「發布 MISSION 鎖定」當下存進 finalized 的實際參戰名單，非團員會加上標記；該時段若尚未發布，才退回用報名名單並在任務資訊處明示。

## 🌟 版本更新 (V1.5.3)

- **戰績排行榜重新啟用**：修正多項導致排行榜數字不可信的問題。
  - `drops` 工作表沒有標頭列，但程式碼固定跳過第一列，導致**第一筆掉落紀錄永遠被吃掉**（實際上整份紀錄就只有那一筆，所以全員掉落數永遠是 0、掉落率永遠 0%）。現在會自動判斷有沒有標頭，有沒有都正確。
  - 團長重複按「發布」會在 `finalized` 留下一模一樣的列，造成**出團次數灌水**（34 列裡有 7 列重複）。現在同一週、同副本、同時段只計為一場。
  - 掉落分配送出後無法確認是否寫入（`no-cors` 讀不到回應），失敗時仍會顯示「結算完畢」並重新整理頁面。現在會重抓資料確認每一筆都落地，失敗時明確提示重送，也不再強制重新整理。
- **戰績統計重新起算**：舊的出團與掉落紀錄已不可考，統計改為從克雷塞爾（樹王）上線的那一週 **2026/9/14** 起重新計算。排行榜標頭會顯示目前的統計期間。

## 🌟 版本更新 (V1.5.2)

- **新副本：克雷塞爾**：新增最新副本克雷塞爾（6 人），順位排在暗黑龍王之後，並設為登入後的預設副本。許願清單提供「克雷塞爾飾品箱」與「楓葉祝福20」，專屬背景色為深海藍。
- **本週次數登記 (Weekly Runs)**：回報空檔時可一併登記本週要打 7 次或 14 次。側欄新增專屬面板統計全團人數，點選時段格子時（電腦、手機皆可）名單也會同步顯示每個人選的次數。此設定僅作登記，不會限制可選的時段格數。
- **克雷塞爾戰術圖**：戰術導覽新增外部戰術圖連結，可直接開啟完整攻略圖。
- **下架普通拉圖斯**：普通拉圖斯已從副本清單移除，舊有的回報資料會被正確忽略，不會誤套用到其他副本。
- **修正「我填完別人看不到」**：過去頁面只在載入當下抓一次資料，之後無論怎麼操作都不會再更新，所以已經開著頁面的人（特別是手機背景分頁）永遠停在舊快照。現在切回分頁或視窗時會自動重新抓取，並新增手動「重新整理」按鈕。
- **送出結果實際驗證**：表單以 `no-cors` 送出，回應讀不到成功與否，加上樂觀更新，導致寫入失敗時只有自己看得到資料。現在送出後會重新抓取確認資料真的存進伺服器；若確認失敗會還原畫面、保留你的選取並明確提示重送。
- **連線重試**：Google Apps Script 有相當比例會回傳 HTML 錯誤頁而非資料，現在會自動重試並擋下壞回應，不讓它汙染畫面。

## 🌟 版本更新 (V1.5.1)

- **Discord 自動排程通知**：新增後端排程功能，每週二 19:00 自動在 Discord 廣播尚未填寫空檔的特務名單；每日 12:00 自動發布今日任務提醒，並附帶系統快速進入連結，徹底落實自動化管理。
- **自動登入優化**：系統現在能自動記錄使用者的裝置。非團長身分的隊員在開啟網頁時將自動帶入並登入（Auto-login），大幅改善使用者的體驗！
- **無縫表單發送 (No-Reload Submissions)**：解決了以往提交排程或是掉落物表單後，系統會自動重新整理頁面強制返回登入畫面的問題。現在所有的資料傳輸都自動在背景完成並即時更新視覺，填寫順暢不再卡死。
- **CORS 例外防護**：修正並避開 Google Apps Script 伺服器重新導向所引發的 Cross-Origin 跨網域存取警告卡死問題，使背景通訊更為穩定。

## 🚀 主要功能

1. **智慧行事曆 (Time Matrix)**：以色彩區塊呈現每天每個時段出團配置，團員只需點擊即可完成空檔登錄。
2. **自動配置及戰術判定**：系統會根據所選的難度，自動判定是否「職業配置齊全」、「人數達標」，並能即時給出檢核警告。
3. **掉落物及戰績榜 (Leaderboard)**：團長配發獎勵後，將自動統計每一個成員的參與次數與戰利品獲得率並顯示在排行榜。
4. **Discord 聯動發布**：一鍵將確認的副本時段、參戰名單、與集合語音頻道自動推送至設定好的 Discord 頻道裡。
5. **安全區浮動視窗 (Picture-in-Picture)**：對於如困難拉圖斯等複雜副本，可開啟專用的戰鬥地圖與輔助參考圖浮層，並自動置頂於遊戲畫面之中。

## 🛠️ 技術架構

- **前端**：HTML5, CSS3 (Tailwind CSS), Vanilla JavaScript
- **後端及資料庫**：Google Apps Script (GAS) 連結 Google Sheets
- **工具/函式庫**：FontAwesome (圖示), Canvas-Confetti (動畫特效)
